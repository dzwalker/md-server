# glossary：术语表（自动下划线 + 悬浮定义，按空间生效）

## 背景

知识库里的业务术语（CLIP、NDS、数据闭环…）散落在各篇文档，读者不知道缩写含义，作者也常中英文混用。希望像维基一样：术语集中维护，正文里出现时自动加下划线，鼠标悬浮即可看定义，且一个术语可以同时有中文名、英文名、多个别名。

## 目标

- **约定**：文件名包含 `术语表` 或 `glossary`（不区分大小写）的 md 文件即「术语表」。
- **约定**：术语表文件内，`## 术语名` 一个术语；`别名：a、b` 声明其它名字；其余内容为定义（完整 Markdown）。
- **自动标注**：空间内所有文档正文里命中术语名/别名的文本加下划线，悬浮显示定义（中英文都支持）。
- **空间作用域**：术语表跟随「空间 set」——同一 set 的多个目录里可以有多个术语表，全部合并生效；不同 set 互不影响。文档目录属于多个 set 时取并集去重。
- **多定义**：同一名字被多处定义时，悬浮只显示前 3 条（按术语表文件路径字典序 + 文件内顺序），提示总条数。
- **长词优先**：`CLIP模型` 与 `CLIP` 同时存在时，文本 `CLIP模型` 命中前者，不会被拆成两个/命中短词。

## 非目标

- 不做术语表编辑器、自动补全、拼写纠错。
- 不做英文词形变化（复数、时态）匹配，严格全词。
- 不做「任意位置全局最长」重叠算法：跨起点重叠按**左优先**（见下）。
- 不做点击来源跳转（浮层只显示来源文件名）。
- 不新增 SQLite 表 / MCP 工具；术语表在渲染时读取。
- 不写任何 md 文件（术语表是只读输入）。

## 约定 1：术语表文件

- `isGlossaryFile(name)`：basename 去掉 `.md` / `.markdown` 后包含 `术语表` 或 `glossary`（`i`）。
  - 生效：`术语表.md`、`术语表-AD.md`、`glossary.md`、`GLOSSARY_neolix.md`。
  - 不生效：`术语.md`、`gloss.md`、`readme.md`。
- 目录里的普通 md 文件，可搜索、可目录，与其它文档无异。

## 约定 2：文件内定义格式

```md
---
title: 项目术语表
---

# 术语表

## CLIP
别名：clip、对比语言-图像预训练、对比语言–图像预训练模型
CLIP 是把图像和文本映射到同一向量空间的对比学习模型。

支持多段、列表、链接、公式。

## NDS
**Aliases:** Neolix DriveStack
Neolix 的数据闭环平台。
```

解析规则：

1. frontmatter 先剥掉（gray-matter）。
2. 代码围栏（``` / ~~~）内的内容不参与结构解析。
3. `#` 一级标题只作文件标题，结束上一个术语块；`##` 二级标题开启一个术语块（标题文本去掉行内 markdown 后作为**主名称**）。
4. 块内以 `别名：` / `别名:` / `Aliases:` / `Alias:` 开头的行声明别名（支持加粗包裹；可多行；分隔符 `、，,;；/|`），别名与主名称一起去重。
5. 其余行是定义正文（Markdown 原文）。**没有定义正文的术语块不生效。**
6. `###` 及以下标题视为定义正文的一部分。

## 约定 3：匹配规则

- **中文**：精确子串匹配（`图像模型` 会命中 `大图像模型`）。
- **英文**：忽略大小写，且严格全词：名字首/尾字符是 ASCII 字母/数字/下划线时，要求前后不是 ASCII 字母/数字/下划线。
  - `CLIP` 命中 `CLIP模型`、`用clip做检索`、`a.clip`（标点算边界）；不命中 `CLIP2`、`clipx`、`a_clip`。
  - `lip` 不会在 `clip` 里命中。
- **长词优先（同起点）**：所有名字合成**一个**正则，alternatives 按字符数从长到短排列；JS 正则在同一位置按顺序尝试，因此长词先命中，失败才回退到短词。
  - `CLIP模型` 命中文本 `CLIP模型` 的整段；`CLIP` 不再单独命中。
  - 文本 `CLIP 模型`（有空格）时长词失败，`CLIP` 命中。
- **跨起点重叠：左优先**。一边扫描一边消费文本，先命中的位置获胜：术语 `语言` 与 `言模型` 遇文本 `语言模型` 只命中 `语言`。这是标注工具的标准行为，不视为 bug。
- **不标注的位置**：代码块、行内代码、链接文字（`[CLIP](...)` 的显示文本）、`[[双链]]` 内部、图片 alt；标注的位置：标题、正文、表格、引用、脚注、笔记卡片（`> note:`）。
- 同一文档内**每次出现**都标注。

## 约定 4：空间作用域与多定义

- 文档的一级目录 → 包含它的所有 set；这些 set 所有目录中的术语表全部合并（同一术语表只算一次）。
- 同一名字多处定义：按「术语表文件 urlPath 字典序 + 文件内顺序」取前 3 条；定义原文完全相同的去重；超过 3 条时浮层显示「共 N 条定义，仅显示前 3 条」。
- 术语表文件改动后：`/api/stat` 的 `glossaryVersion` 变化，已打开文档在 5s 轮询内自动重拉渲染。

## API 变化

`GET /api/render/*` 响应新增：

```jsonc
{
  "glossaryVersion": "1a2b3c",
  "glossary": {              // 仅本文档命中了术语时给出
    "version": "1a2b3c",
    "terms": {
      "clip": {
        "names": ["CLIP", "对比语言-图像预训练"], // 大小写同名（clip）规范化后去重
        "total": 4,
        "defs": [
          { "source": "术语表.md", "html": "<p>定义渲染后的 HTML</p>" }
        ]
      }
    }
  }
}
```

正文里命中的文本渲染为 `<span class="glossary-term" data-glossary="clip">CLIP</span>`；`data-glossary` 是规范化名字（英文小写、trim、压缩空格），与 `glossary.terms` 的键一致。

`GET /api/stat?path=` 响应新增 `glossaryVersion`（无术语表时为 `""`）。

## 验收标准（Given-When-Then）

1. 空间 set 含目录 a、b，a 里有 `术语表.md`（含 CLIP），b 里有 `glossary.md`（含 NDS）→ a、b 下任意文档两者都生效。
2. set `p` 不含目录 a → a 下的术语不会在 p 的文档里下划线。
3. 术语表定义支持别名：`## CLIP` + `别名：clip、对比语言-图像预训练` → 文本里 `CLIP`、`clip`、`对比语言-图像预训练` 都标注，悬浮显示同一份定义。
4. `CLIP` 与 `CLIP模型` 同时定义 → 文本 `CLIP模型` 只有一个覆盖全词的标注（`data-glossary="clip模型"`），文本 `CLIP 模型` 命中 `CLIP`。
5. `CLIP` 不标注 `CLIP2`、`clipx`；`lip` 不标注 `clip`。
6. 同一名字被 3 个以上术语表定义 → 浮层只显示 3 条，并提示总条数。
7. 代码块、行内代码、链接文字里的术语不标注。
8. `> note:` 笔记卡片里的术语同样标注。
9. 未传术语时渲染结果与改动前逐字节一致（不传 term index 时插件不生效）。
10. 修改术语表（增删术语/改定义）→ 已打开文档 5s 内自动更新下划线与浮层内容，无需刷新。
11. 悬停下划线文本 → 浮层出现在可视区域内（下方不够时翻到上方），移入浮层保持打开，移出/滚动/Esc 关闭。
