# spec: 资源管理器文件树右键菜单（复制文件名 / 复制完整路径 / 下载）

## 背景

- 资源管理器（`web/src/components/sidebar/tree-view.tsx`，react-arborist）此前只有左键：文件夹展开/收起、文件打开文档。
- 想拿到一篇文档的**文件名**或**路径**（丢给终端/给 AI 当上下文/写进别的文档），只能先打开文档、再从地址栏或标题里拼；想拿**磁盘原文**，必须先进文档再点右上角下载按钮。
- 文件夹此前完全没有"取出它的路径"的办法。

## 目标

1. **文件节点右键**：`复制文件名` / `复制完整路径` / `下载`（三项，顺序固定）。
2. **文件夹节点右键**：`复制完整路径`（仅一项）。
3. 内置的虚拟「工具」节点（`/__tools__` 及其子节点）**不提供**右键菜单——它们的 path 不是磁盘上的真实路径，复制出去没有意义。
4. 操作后有轻提示（「已复制文件名：x.md」/「已复制路径：/…」/「下载失败」），1.8s 自动消失。

## 非目标

- 不做重命名 / 删除 / 新建 / 移动到（生产 md 数据只读，见 `AGENTS.md`）。
- 不做文件夹打包 zip 下载。
- 不改 ⌘P / ⌘O、左键行为、树的展开状态持久化。
- 不动后端 API、索引与 `src/`（纯前端改动）。
- 不违背「复制文件名」的语义去复制文档标题：给的是**磁盘真实文件名**（带 `.md` 扩展名）。

## 验收标准（Given-When-Then）

**A. 文件节点**

- [x] Given 树上任一 md 文件，When 右键，Then 菜单按固定顺序显示 3 项：`复制文件名`/`复制完整路径`/`下载`，且无其他项。
- [x] Given 文件节点菜单，When 点「复制文件名」，Then 剪贴板得到磁盘真实文件名（如 `note-a.md`，带扩展名；不是显示的文档标题）。
- [x] Given 文件节点菜单，When 点「复制完整路径」，Then 剪贴板得到应用内 urlPath（如 `/spaceA/note-a.md`），与 `/api/tree`、收藏、搜索里的 `path` 完全一致。
- [x] Given 文件节点菜单，When 点「下载」，Then 浏览器下载该文档的**磁盘原文**（`/api/files/*`），文件名 = 真实文件名，内容与磁盘一致（不是渲染后的 HTML）。
- [x] Given 任意一项被选中，Then 菜单自动关闭，轻提示出现，无 console error。

**B. 文件夹节点**

- [x] Given 任一文件夹（含空间根与嵌套目录），When 右键，Then 菜单**只有** `复制完整路径` 一项（没有「复制文件名」「下载」）。
- [x] Given 文件夹菜单，When 点「复制完整路径」，Then 剪贴板得到该目录的 urlPath（空间根如 `/spaceB`，嵌套如 `/spaceA/sub`）。

**C. 虚拟工具节点**

- [x] Given「工具」目录或其子节点「图谱」，When 右键，Then 不弹出自定义菜单。

**D. 兼容与降级**

- [x] Given 当前文档已打开，When 点文档头右上角下载按钮，Then 行为与改动前完全一致（共用 `downloadDocByPath`）。
- [x] Given 非安全上下文（http + 非 localhost，如局域网 IP 打开），When 复制，Then 走 `execCommand` 降级，仍能复制成功。
