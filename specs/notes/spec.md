# spec: 正文笔记（`> note: 内容` 一行）——右键插入 / 就地编辑 / 删除

## 背景

- 预览页（`web/src/components/doc-view.tsx`）此前是**只读**的：读到一段想批注、想记「这里待确认」「这段的出处」，只能另开一篇文档或切到别的编辑器手写 md，批注与上下文脱节。
- 服务端此前**没有任何写文件的接口**（全部是 GET + 收藏/空间配置的 POST），md 文件对应用而言是只读数据。
- 目标是让笔记落在**文档本身**、用**现有 md 语法**：一条笔记 = 文件里独立的一行 `> note: 内容`。它借用引用块语法，因此在 Typora / Obsidian / GitHub 等其它工具里也能正常显示，不需要专有格式、不需要旁挂存储。

## 目标

1. **语法**：一条笔记 = md 文件里的独立一行，`> note: 内容`（`>` 与 `note:` 之间的空格可有可无，行首允许最多 3 个空格缩进）。内容支持**行内 markdown**（加粗、`[[双链]]`、`$公式$` 等，与正文同一套渲染规则）；**单行**语法，不允许多行续写。
2. **渲染**：服务端把它渲染成「笔记卡片」（左侧强调色边 + `笔记` 标签），与普通引用块视觉区分；卡片上带行号与**原始 markdown**（供就地编辑取初值）。
3. **插入**：正文右键 → 菜单**只有**「插入笔记」→ 就地出现编辑器 → 保存后把这一行插在**右键所在块之后的一行**（不额外插空行、不跑到文末）。
4. **编辑 / 删除**：已有笔记上右键 → 菜单为「编辑」「删除」；编辑就地改这一行；删除**必须二次确认**。
5. **取消不落盘**：插入与编辑都提供「取消」（也支持 `Esc`），取消后磁盘文件**逐字节不变**。
6. **写盘边界**：新增的写接口只允许改「被识别为笔记的行」——插入新行 / 改写已识别的笔记行 / 删除已识别的笔记行；不提供通用覆盖写，绝不动其它行。并发用 `mtimeMs` 乐观锁：客户端渲染后文件若被外部改过，写入被拒绝（409）并提示，不覆盖。
7. **保存后即时反馈**：正文立刻重渲染反映磁盘新内容（编辑器随之消失），并立即重新入索引（全文检索、双链、最近更新同步）。

## 非目标

- 不做移动端长按菜单（右键是桌面优先交互）。
- 不做多行笔记、富文本、图片/附件笔记。
- 不做笔记汇总面板 / 独立的笔记搜索入口（笔记文本本来就在全文索引里）。
- 不改旧兜底前端 `public/index.html`（仅在未构建 `web/dist` 时使用）。
- 不新增 MCP 工具、不改现有 MCP 工具签名。
- 不做笔记级权限/多人协同（单机自托管个人应用）。

## 验收标准（DoD）

- [x] `> note: 内容` 渲染成笔记卡片，带 `data-note-line`（行号）与 `data-note-raw`（原始 markdown）；行内 markdown 正常渲染。
- [x] 不误伤普通引用块（`> 普通引用`、`> notes:`）与四空格缩进的代码块。
- [x] 每个顶层块带 `data-line-start` / `data-line-end`，右键可定位「插在这一块之后的一行」。
- [x] 正文右键菜单：普通块 = 仅「插入笔记」；笔记卡片 = 「编辑」「删除」。
- [x] 插入 / 编辑为就地 inline 编辑，有「保存」「取消」；`Enter` 保存、`Esc` 取消，中文输入法组字过程的 `Enter` 不算提交。
- [x] 取消（含 `Esc`、切文档、换主题重渲染）不写盘、磁盘逐字节不变。
- [x] 删除有二次确认弹窗；取消确认不删。
- [x] 保存后正文立刻更新；磁盘上只在目标位置多/改/少那一行，CRLF、末尾换行、文件权限保持。
- [x] 写接口只作用于笔记行：对正文行做 update/delete 一律 409，文件不动。
- [x] `mtimeMs` 乐观锁：文件被外部改动后写入返回 409，前端在编辑器内显示提示，磁盘不被覆盖。
